# Tooling

Manual Android packaging must preserve inference dependency service descriptors and root properties alongside D8 output, without adding a second copy of the host's Guava or Kotlin runtime. Fingerprint resolved dependencies and packaging inputs, including the library's authoritative ui/ directory; do not hide availability or operational failures behind discovery abstention. Toolkit host checks must execute the current DEAL 1.4 compiler and production JS loader/session, mock only external boundaries, assert exact packaged inputs and record revisions plus hashes. Do not reintroduce historical compiler/pack compatibility lanes; test current source and settled-state restoration. Keep private saved-source fixtures and receipts under ignored build output.

Selection prototype probes are isolated from shipping generation and device state. Preserve every live response, validate exact native arguments without JSON correction, and keep model-authoring failures distinct from supplied-plan runtime passes. Run deterministic compiler/runtime verification before opt-in inference; credentials remain inside a loopback gateway and no build may overlap inference. Host verifiers consume build/embedding-library and embedding-consumer; do not overlap them with a library rebuild that removes/replaces those inputs.

Formula parser tests must cover forbidden source syntax, binding preflight, nested dependencies and precedence; arithmetic integration also runs through the production emitter/compiler/session, not a second evaluator.

Behavioral plan fixtures belong only in host/device tests, never generation guidance or library operations. Maintained-fragment tests must supply only requirements and disclosed bindings; exercise the resulting state/handlers/views through real compiled runtime. Include failed refresh after success, input edits during outstanding reads, delayed sequential replies spanning TTL and stock-qualified alternatives. Exercise the production emitter, current compiler and production loader with opaque varied provider IDs and whole-basket replies; fixture compilation is not live intent selection or measured delivery. Replay captured plan arguments read-only from ignored private artifacts; verify rejection diagnostics without repairing captured input or exposing it in production guidance. Route/custom-volume/operation accounting must survive content-artifact eviction.

Keep library builds independent of consuming apps. App policy builders compile trusted DEAL and package authored source without selecting semantic answers. Credentials stay in the existing loopback gateway, never generated assets or receipts. Host APKs select cortex/cerebras through DEAL_GENERATION_BACKEND at build time; Cerebras is the default. Preserve the requested backend when rebuilding and inspect the installed selection plus actual request evidence, not just the gateway default. Select discovery independently with DEAL_DISCOVERY_BACKEND=nano/deepseek-flash; retain local inference and keep cloud opt-in separate. The external gateway alone reads DEXTER_DEEPSEEK_API_KEY. Benchmark purges require explicit authorization, archive first, preserve domain/authority and old measurement directories, and verify zero saved source/drafts/links before any inference. Generated host bootstrap supplies endpoint/backend configuration to embedding's library-owned gateway client; do not compile an app-owned connection implementation. The client forwards that explicit selection, never silently switches providers. Keep provider parameterization and credentials in the external gateway, not app domain code or embedding's portable runtime.

Aggregate generation metrics from unified events using latest request-summary revisions and unique repair IDs. Keep unknown usage out of known denominators, report sample counts and revisions, and require explicit test evidence for usefulness/preservation. Receipt phase timing is not model compute; source locality is not semantic preservation.

Distinguish deterministic compiled-policy checks, real-device interaction checks, live-model evaluation and visual acceptance. Presentation capture/check tooling must explicitly leave visual review pending; screenshots and UI-tree checks alone do not establish design quality. Capture task, suggestion, pending, empty, failure and Inspect states without silently injecting expected model output. Keep initial/repair reasoning effort and completion limits independently configurable in the external gateway, using provider-documented values only. Stream measurement may collect receipt timestamps/counters but never execute partial source or retain/print hidden reasoning. Preserve invariant system prefixes, exclude duplicate patch bases, and verify actual cache counters. Source reasoning must stay enabled; remove disabled-reasoning experiments rather than retaining a dormant option. Initial source generation uses provider-native strict submit_compact/submit_custom/source_fallback tools. submit_compact selects independently named maintained fragments with actual nested configurations, semantic ports/formulas and command targets; submit_custom exposes the separately measured lower-level graph/custom bodies. Load their shapes from embedding-owned contracts; do not duplicate raw-code compact schemas. Distinguish maintained-only/custom-section/full-source coverage from catalogue origin and retain fallback reasons, custom volume and source-repair transitions. Select tools from core-authored workspace phase: no parallel compact calls; write_file only after explicit fallback; read/edit/check only once materialized. Portable core owns phase transitions, the two-file workspace, revision binding, admission and feedback; the gateway never assembles plans or executes tools. Never retain raw framing, model-authored pair/patch envelopes or fallback extraction. Catalogue choices and API/internal serialization remain JSON. Provider adapters must assemble streaming tool arguments without executing partial calls, discard hidden reasoning and preserve usage/receipt counters. Enable multi-call responses only when core's initialWrites workspace metadata allows them, not merely when the complete previous pair is absent. Preserve interleaved indexed initial-write arguments and native tool-result identities. Keep strict read_file bounds required-but-nullable at the provider boundary, allowing full reads without imposing a range-size ceiling; core owns range validation and literal numbered results. Repairs are only revision-bound exact patches, never full rewrites or strategy-selected fallbacks. Treat iterative repairs as normal for complex cases; optimize locality, latency and behavior preservation, not a zero-repair target. Report provider reasoning-token counts separately from completion totals and elapsed time; missing counts are unknown, not zero, and hidden reasoning text must never appear in reports. Live checks require explicit opt-in, retain failed attempts and never inject an expected answer. Framework recovery remains within the same request and records every retry; programmatic runtime tests may return actual failed assertions as feedback for targeted repairs. Never use manual retry taps as an e2e recovery mechanism. Device fixtures may replace labelled demo records only. Enriched-journey setup adds absent-only isolated review records with realistic task names; never overwrite existing records, saved source/state, failed evidence or authority. Keep fixture provenance in tooling/Inspect rather than acceptance instructions on the task canvas. Compare private before/after archives to establish preservation. Shell UI checks must enter the same Settings/Inspect classes in all apps, keep proposal confirmation separate, and test reset cancellation without deleting existing user experiences. Destructive reset behavior belongs in isolated native regressions unless explicitly approved for device data. Store private screenshots/logs under ignored build output, not tracked documentation.
