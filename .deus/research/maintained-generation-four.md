## Implementation

Replaced the raw-body compact composer with a closed typed graph emitter. Maintained operations cover arithmetic, formatting, projection/filter/join/aggregation, immutable keyed edits, constrained allocation, component-ID matching, basket serialization and ordered capability workflows. Capability records remain provider-owned. Initial construction emits canonical DEAL/Deal UI once; all later repair uses revision-bound atomic exact edits. Custom typed sections and full-source fallback remain explicit, distinct routes. No selector/verifier model call was added.

Added minute-of-day TimeField, direct integer entry and resumed-lifecycle SessionClock. Generated DEAL owns freshness policy; native lifecycle signals invalidate trust and fence stale completions. Pizza now discloses numeric diameter and rejects malformed deadlines rather than substituting a time.

Generation bridge producers are evaluated once and drained losslessly in bounded JSON chunks. Active repair history retains the latest native exchange plus current canonical pair/diagnostic, not every historical source copy. Complete prior evidence remains observable.

## Observed verification

Tests exercise edits, restoration, ownership, travel lookup, menu/delivery sequencing, six-item allocation/category minima, infeasible editable rows, late-window invalidation, provider failure, component resolution, whole-basket quotes, expiry and resume invalidation. Typed joins, fractional optional results and explicit custom computation are tested separately.

Android maintained fixtures passed all four plans and exact bridge transfer beyond 512 KiB, including Unicode, CRLF and NUL with a single producer evaluation. Canonical native Pizza/Rental handlers passed strict deadline/basket/period validation and authoritative attribute/component/price/deposit checks. Protocol regression passed. Native renderer defaults passed omitted/enabled/disabled action-state and payload tests.

A repair instrumentation assertion initially assumed a fixed tree position; the emitted wrapper made that invalid. The test now locates the compiler-issued action recursively. Earlier diagnostic-history failure led to retaining current repair guidance on each turn. These intermediate failures are preserved privately, not counted as successful delivery.

Host gateway/transport, source-agent, source-repair, protocol, guidance, cohort-collector and API-mirror checks pass. Installed Organizer, tests and Pizza bytes were independently compared with built APK hashes. Tests were rebuilt after the tree-selector correction; final gateway regression passed configured generation, checked edit/reopen, exact repair, backend/path forwarding, chunked HTTP, typed failures, cancellation and capture policy.

## Recovery hardening after renewed authorization

Read-only replay of all 140 captured plan arguments reproduced admission independently of inference: one of 15 budget plans was accepted; all 125 departure plans were rejected. Combined diagnostics identify 109 plans with nonboolean invalidation entries and 117 with omitted call projections; these counts overlap. No rejected captured plan was silently repaired or promoted. Replays check admission only, not task semantics.

Maintained component facts now use bare names, prop types/defaults and event contracts, not executable `ui.Component(...)` or action source. Guidance explicitly separates state declarations from derived assignments, event payload from action fields, boolean validity from numeric cached data, and scalar/record result projection. The emitter reports independent binding failures together with plan paths while leaving the workspace unchanged. Four maintained compiler/runtime fixtures still pass; gateway and collector tests pass. Route/custom-volume/operation metadata now survives content-artifact eviction, including a compiled-logger regression for metadata longer than the previous 160-character target cap.

The recovery build was installed and byte-verified for Organizer, tests and Pizza. This establishes verification of the correction, not live-model adherence or speed. Any subsequent cohort must have a new archive and retain the failed cohort unchanged.
