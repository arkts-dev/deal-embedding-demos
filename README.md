# Native DEAL experiences

Calendar, Todo and Vehicle are native Kotlin applications with a shared Compose Material 3 Expressive theme. Calendar checks received `.deal` and `.dealui` source on-device, generates DEAL through the existing Deal UI checker, compiles JavaScript locally and mounts a persistent JavaScriptSandbox store. The reusable Compose renderer consumes the checked portable tree. Application state, updates, task selection, route adjustment and async departure calculation remain in DEAL. There is no WebView presentation. Calendar accepts an intent and uses real remote model inference through a development-machine gateway; checking, compilation and activation remain on-device.

Build with `./tools/build.sh`; `./tools/build.sh calendar` builds only the experience host. Install `build/calendar.apk`, `build/todo.apk` and `build/vehicle.apk`. The build requires JDK 25, Kotlin with its Compose compiler plugin, Android SDK API 37 and build tools 36. Apps target API 36. Runtime libraries are digest-pinned. Gradle resolves Compose dependencies; javac, kotlinc, aapt2, D8 and L8 construct APKs on the desktop. No DEX compilation or APK installation occurs during experience activation.

# Hosting and framework seam

`android/apps/` owns Calendar, Todo and Vehicle; `android/apps/shared-ui/` supplies native demo styling; `android/apps/development/` owns the loopback inference client used by Calendar and instrumentation, not by the embedding library. Todo and Vehicle declare typed contracts and native handlers once in their own `*Capabilities.kt`. Their services publish those contracts through the embedding library's generic capability protocol. Each provider owns caller authentication and independent consent; neither imports the other provider.

Calendar's `CalendarCapabilities.kt` exposes only selected event context and staging a proposal. `CalendarEmbedding.kt` discovers services by the versioned protocol action, applies a signer trust policy and supplies native grants. It knows no external package, method or record shape. Provider contracts drive checker declarations, sandbox bindings, native argument/result validation and DEAL table conversion. This is an explicit participating-provider integration protocol, not an Android standard or access to arbitrary apps.

`dependencies/deal-embedding/` owns its library build and documented public API in `dev.deal.embedding`. It produces `build/embedding-library/deal-embedding.aar`, with compiler classes and framework assets from DEAL and Deal UI. Calendar compiles against the extracted AAR, not compiler or embedding source directories. `EMBEDDING_AAR` selects a prebuilt artifact and skips the dependency build entirely. The library imports no app packages and contains no provider adapters. The app supplies discovered contracts through `EmbeddingConfig` and uses `CapabilityRegistry`; internal compilation and sandbox sessions remain behind `ExperienceRuntime`.

`android/apps/calendar/experiences/departure/` contains Calendar's generated sample `.deal` and `.dealui` payload. The supported `.dealui-pack` belongs to the embedding dependency. `EmbeddedExperience` gives mounted generated content a labelled violet surface and nested color theme; Calendar's green agenda, consent and confirmation remain outside that boundary.

# Real generation

Start `python3 tools/generation-gateway.py` on the development machine and run `adb reverse tcp:8787 tcp:8787` for the selected device. The gateway reads the configured `devagent` / `cortex` credential from Pi's local configuration in memory, binds only loopback and does not log requests, prompts, credentials or provider responses. Nothing secret is packaged in the APK. The development client only accepts the forwarded loopback endpoint; cleartext transport is a development exception, not a production remote gateway design.

Calendar's native intent field, Generate/Cancel controls and status invoke the compiled trusted `core/generation.deal` workflow. Native adapters return the discovered catalog, call the model and check candidate source. The workflow builds input and tries one bounded template-choice inference first; unsupported choices fall back to source generation with at most two repairs using structured diagnostics. Checked template defects stop without inference repair. Version-matched write-deal guidance, Deal UI guidance and the supported component pack accompany every model call. The model selects issued template aliases or produces `.deal + .dealui` source and cannot grant permissions, invoke providers or activate replacements.

Only explicitly checked selected-event context is sent; generation never reads task or travel data. Capability descriptions are sent to the model. The host rechecks disclosed selection before activation. Invalid output, exhausted repairs or cancellation retain the mounted experience. A newly generated workflow mounts with fresh state; ordinary source replacements retain compatible state. Both refuse replacement during outstanding effects. Remote cancellation prevents activation but does not establish remote-provider compute cancellation.

# Source and rendering

The pregenerated departure bundle is received through the same compiler path as replacement source. Android intents supply `deal` and `dealui` string extras. Both files are checked and compiled in a candidate directory. A candidate isolate must mount before replacing the live session. Invalid candidates retain the mounted experience. Compatible replacement bundles retain generated state; incompatible state rejects replacement rather than resetting silently. Replacement while an effect is outstanding is rejected. Event selection and provider data remain native and survive replacement.

The session consumes compiler-issued action factories, nominal validation, queue lifecycle, update handlers, reconciliation plans and async completion actions. Compose uses structural and collection-key identity. The host rejects unsupported component capabilities and currently rejects effect-policy and failure-mapper programs rather than approximating their semantics. This renderer supports the bundled checked component pack, not every Deal UI component pack. Two-second evaluation deadlines close runaway isolates; heap and returned-output bounds apply. The compiler still runs in the trusted host process without independent resource isolation.

# Data and authority

Calendar Provider supplies upcoming events. Native permission controls reading and writing, and native event selection supplies the selected start time. Todo persists tasks and completion state. Vehicle exposes explicitly simulated travel time, not traffic or telemetry. Generated DEAL retains task selections by stable provider identity, adjusts breathing room and route distance, and recalculates through async effects.

Provider owners consent independently in Todo and Vehicle. Calendar also grants access locally. Calendar selects trusted provider signers; providers authenticate the actual Calendar UID, package and signer. Callbacks must match the discovered provider UID. Revocation cancels pending work, stale callbacks cannot re-enter a session, and provider death rejects pending work. Generated code cannot grant access or write provider data.

A typed Calendar proposal is not a write. Only a native confirmation adds a Calendar Provider reminder. Confirmation checks the selected event, re-reads its instance, and performs a conditional event update and reminder insertion in one provider transaction. Existing reminders are retained. Minute-of-day planning currently requires a same-day departure; recurring-event instance-specific exceptions and overnight travel are not implemented.

# Saved-workspace debugging

Organizer debug builds accept `--es replayWorkspace <saved-workspace-id>` on a cold activity launch. Replay reads existing app-private source, checks it locally and opens a fresh workspace without inference; it accepts no injected source. Dispatch/poll failures go to logcat and app-private `workspace-error.txt`, separately from the last published `workspace-snapshot.json`. Organizer polls live workspace completions on its serialized worker.

After building/installing Organizer and `tools/build.sh tests`, run `adb shell am instrument --user 0 -w dev.deal.connectors.tests/.WorkspaceInstrumentation`. It requires saved Organizer source reading `host.staged()` and uses an explicitly read-only fixture to check independent request IDs, reply isolation, close isolation and grant revocation without model calls.

# Organizer catalogue flow

A single selected equipment requirement discloses its quantity, specification, search terms and exact time interval. Issued catalogue adapters require a bounded array of typed equipment records and correctly typed disclosed arguments; operations history is not a catalogue. The generated DEAL reads matching options, shows price/availability, retains selection and stages a populated descriptor in Organizer's native review. Name/specification matching is a candidate filter, not proof of technical suitability. No Rental quote, proposal or reservation write is called by this template. Native review currently does not connect provider confirmation; it says so rather than claiming a reservation was made.

`CatalogueInstrumentation` checks all eight supported presentation combinations without remote inference, typed period forwarding, filtering, prices, unavailable options, selection, staging and failure ownership. Catalogue eligibility/aliases/answer validation execute in `core/choice-policy.deal`. `node tools/verify-choice-policy.js` compares compiled policy with frozen pre-migration decisions across positive/negative schema/context fixtures, dynamic parameter keys and UTF-16 bounds. Deterministic slow-path tests inject invalid source, repair it through the same checker/mount path, and verify exhaustion preserves a healthy workspace.

`core/catalogue-source.deal` owns the catalogue template, filtering-expression construction, presentation and descriptor wording; `core/candidate-check.deal` validates source envelopes. Composition rules and prompt formatting live in `core/generation-guidance.deal`; Java extracts asset text and pack facts only. `node tools/verify-core-migration.js` verifies exact pre-migration source/prompt parity, escaping, envelope rejection and fatal-host propagation.

Routine app-private `embedding-receipts.jsonl` records correlate generation, checks, mounting, actions, capability completion, produced snapshots and native publication without payloads. Raw replay traces require explicit `embedding-debug.captureReplay`; ordinary logging no longer records model source or answers. Run `adb shell am instrument --user 0 -w dev.deal.connectors.tests/.CatalogueInstrumentation` after installing Organizer and tests. `tools/verify-organizer-catalogue.py` performs one real generation through native controls; `--replay <saved-id>` repeats the downstream flow without inference. It requires Rental owner consent and checks that provider persistent state remains unchanged. Accepted source and receipts remain under ignored `build/`.

# Verification

`tools/CheckExperience.java` invokes the same in-process checking and source-generation entry as Android against declarations captured from actual provider discovery by the device verifier. `node tools/verify-ui-session.js` checks mounted rendering, action-driven state, async completion, keyed task selection, state restoration, stale-action rejection and disposal against locally compiled source. `python3 tools/verify-experience.py` exercises actual Compose controls and checked trees, connected providers, invalid-bundle retention and post-install replacement with unchanged PID and package installation metadata. It requires an upcoming Calendar Provider event and the apps installed. `python3 tools/verify-experience.py --late-provider` installs an unknown test provider after Calendar starts, discovers its published travel contract and executes the pregenerated experience without changing Calendar's PID or installation. Device receipts and screenshots stay under ignored `build/`.

`python3 tools/verify-generation.py` exercises native intent entry, two real model-generated workflows, their controls, discovered travel invocation and cancellation on the attached device with unchanged PID/install. `GenerationInstrumentation` runs the compiled trusted workflow against real inference; explicitly injected invalid output exercises structured diagnostic repair by the real model, bounded exhaustion, cancellation retention and rejection of orchestration imports. `python3 tools/verify-boundaries.py` checks core/host contracts and Android compiler/bindings separation, compiled orchestration packaging, absence of credentials, AAR asset consumption and independent provider packaging. The instrumentation APK has separate Todo and Vehicle checks, each proving rejection of a same-signer non-Calendar UID. Earlier scalar probes and widget-only verification scripts have been removed. Full-language suites have not been rerun for this deliverable. Physical-device compatibility, production distribution/signing, broader renderer packs, on-device model inference, comprehensive accessibility review and compiler resource isolation remain unverified.
