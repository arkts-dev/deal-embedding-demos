Always deliver a complete end-to-end user story through one clear user-facing facade: with setup complete, open the app, discover useful help, tap to use it, change an input, observe the result and reopen it. Inspect owns implementation details and accountable evidence. Keep it reachable before generation and after failure, scoped through public trace/experience observations. Returning from Inspect must not retry failed inference; recovery is an explicit user action. Competing legacy entrances, extra engineering confirmations or instructions to avoid the wrong button are integration defects, not follow-up suggestions. Verify the actual installed journey before declaring completion; developer setup does not count. Capability descriptions must specify executable argument semantics and prerequisites, not just types. Reject malformed/empty baskets and invalid periods rather than supplying successful defaults; package availability must account for shared component stock.

Use one shared AssistanceSettingsActivity and AssistanceInspectActivity across every app and entry point; keep native themes but no app-specific copies or extra diagnostic tabs. Settings is the sole assistance/access authority UI. Native proposal review stays a separate task surface, never another sharing switch. AssistanceShell selects app storage and scope, stops registered owners before confirmed reset, forgets through the public protocol and clears only generated links/dismissals. Preserve domain records, permissions, grants, disclosure/capture choices and failure evidence. Do not run reset on upgrade/startup or silently retry failed cleanup. Register new owners for reset and fence generation before forgetting. Keep only the current app namespace; do not retain retired test-store enumerations, obsolete diagnostic receivers, singleton bootstraps or presentation fixtures for deleted product facades. An explicitly requested historical-data purge is separate from the ordinary evidence-preserving reset. Build-selected remote discovery must have its own cloud-disclosure opt-in; never inherit local inference consent. Repairs belong exclusively to embedding's targeted exact-patch path; do not add app-owned repair logic, strategy flags or rewrite fallbacks. Apps supply only native bootstrap configuration to library-owned discovery transport.

Shared app-shell helpers may own demo trust/sharing policy, disclosed facts, lifecycle/placement/retention choices, native themes and public-protocol Inspect presentation. They must not implement compilation, generated state, renderer dispatch, update pumping or provider transport; those remain in embedding. Directory names do not establish this boundary—verify actual call paths. Remove superseded code, not still-used native app features or relevant regression coverage.

Treat functional acceptance and visual acceptance separately. Ordinary screens contain the user's task, controls, concise status and necessary consent—not implementation narratives. Inspect owns technical details; setup/access controls do not occupy the task canvas. Read the active design guidance before changing native or generated presentation. Capture real device states and review their screenshots for hierarchy, density, action visibility and controls/result proximity. A successful build, UI-tree assertion or working tap is not a visual review. When images cannot be reviewed, report visual acceptance as open rather than declaring UI completion.
