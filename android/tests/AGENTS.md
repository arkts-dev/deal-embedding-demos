# Android tests

Discovery boundary tests use injected inference and real protocol admission; live Nano checks require explicit opt-in and retain semantic failures separately from parser/availability errors. Calendar confirmation checks use a controlled dedicated-demo event and delete it afterward. Keep live expectations out of initial model input. Explicit runtime-test failures may enter subsequent framework repair feedback; retain each rejected candidate and do not implement retries in the test runner. Gateway fixtures use local HTTP servers and the compiled generate path; verify backend/path forwarding, checked interaction, cancellation, bounded errors and capture policy without live model calls.

Inspection regressions must read events/artifacts through ApplicationProtocol and use canonical experience/session identifiers; test transitive handoffs, missing/incomplete evidence, capture-off/nonretroactive snapshots and publication separately from production. Keep native-storage corruption tests confined to explicit observation failure checks. Exercise capture across simultaneously active protocol/Inspect instances, including reader closure and nonretroactivity. Settings tests use isolated shared preferences and preserve explicit OFF; do not retain obsolete consent-migration fixtures. Failure-recovery tests inject failures rather than using live inference and distinguish explicit retry from lifecycle resume.

Rental read-validation tests use isolated preferences, exercise the real canonical native handlers and preserve installed sharing/domain records. Assert rejected malformed baskets/periods, exact totals and component-stock consumption, not just schema-valid replies. Exercise source-bound draft retention across actual process/XML reloads, cold protocol reconstruction and concurrent Inspect-style readers, not only close/run on one instance. Common-shell reset tests use isolated app contexts, real saved source/drafts and registered owners. Check all app namespaces, owner-close failure, idempotence, cold empty reopening and preservation of authority/domain/evidence. Never flush installed personal data for automated checks. Exercise Settings confirmation/cancel and common Inspect scope separately on device. Prefer short regressions through real compiled artifacts and framework adapters. Keep deterministic model fixtures distinct from live inference evidence. Use controlled test/demo records only, preserve personal records and cleanup issued resources. Do not add source-pattern assertions as substitutes for functional session checks. Guidance and toolkit regressions consume the exact library-packaged ui/ source pairs, with fixture-only host/sample and explicit empty/pending/success/failure/retry; never expose that capability to ordinary apps. Toolkit fixture screens use the real compiler/runtime and ExperienceSurface with realistic task content; engineering facts belong behind Inspect. They verify native component states, never replace ordinary app journey acceptance. Additive Calendar review setup remains test-only, absent-only and independent of grants or generated source. Verify explicit comparison status, bounds, payloads, typed dynamic children and cold retention independently from device visuals and model adherence.
